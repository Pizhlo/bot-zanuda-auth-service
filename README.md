# bot-zanuda-auth-service

Сервис авторизации - сервис, проверяющий права пользователей на выполнение действий и чтение данных.

В корне проекта лежат важные файлы, необходимые для работы сервиса и запуска автотестов.
* `Dockerfile` - используется каждый раз в пайплайнах, чтобы сбилдить образ.
* `migration` - папка с миграциями. На старте сервис берет миграции оттуда и применяет к БД.
* `testdata` - тестовые данные для локального тестирования и прогонов тестов в пайплайне.
* `docker-compose.yaml` - файл для запуска окружения в докере.
* `docker-compose.tests.yaml` - файл для запуска автотестов в докере.


## Команды

Запустить линтеры (установить перед этим командой `make init`)
```sh
make lint
```
Запустить тесты:
```sh
make test
```

Запустить сервис (нужен `postgres`, `redis`, `vault`):
```sh
make run
```

# Автотесты

Для корректной работы автотестов должны быть указаны следующие переменные:
* `AUTH_SERVICE_PORT` - порт, на котором развернут сервис.
* `BOT_API_KEY` - апи-ключ бота для авторизации в сервисе. Сохраняется в `vault`.
* `CONFIG` - конфигурация для сервиса.
* `DOCKER_PASSWORD`, `DOCKER_REPO_NAME`, `DOCKER_USERNAME` - данные для авторизации в `docker`.
* `MIGRATIONS_PATH` - путь к миграциям.
* `POSTGRES_DB`, `POSTGRES_HOST`, `POSTGRES_PASSWORD`, `POSTGRES_PORT`, `POSTGRES_USER` - данные для доступа к БД.
* `PYTESTS_CONFIG` - конфигурация для автотестов.
* `VAULT_ADDR` - адрес, на котором развернут `vault`.
* `VAULT_CONFIG` - конфигурация `vault`.
* `VAULT_DEV_ROOT_TOKEN` - токен для `vault`.
* `VAULT_PORT` - порт, на котором работает `vault`.
* `VAULT_SECRETS_PATH` - путь, по которому лежат секреты в `vault`.

## Важные особенности
Для корректной работы пайплайнов путь до секретов необходимо указывать по-разному.
* Для сервиса: начиная с `secret/data/...`
* Для автотестов: без `secret/data/...`
* Для `vault`: без `data` - `secret/...`
